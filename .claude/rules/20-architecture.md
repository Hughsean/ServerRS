# 架构与分层规则

## 依赖方向

- 保持由外向内依赖：接口层调用应用层，应用层依赖领域抽象，基础设施层实现领域抽象。
- 领域层不应依赖 Web 框架、数据库 ORM、消息队列、HTTP 客户端、具体配置格式或外部 SDK。
- 应用层负责用例编排、事务边界、权限检查、状态流转和领域服务调用。
- 基础设施层负责数据库、缓存、文件系统、网络、外部 API、消息队列、向量库等具体实现。
- 启动/装配层负责构造依赖、读取配置、注册路由、挂载中间件和启动后台任务。

## 修改原则

- 新功能先判断应放在哪一层，不要把所有逻辑塞进 handler/controller。
- 不要让接口层直接操作数据库实体或外部 SDK，除非项目现有架构就是这样。
- 不要让基础设施细节泄漏到领域模型、DTO 或公开 API 中。
- 新增跨层能力时优先定义 trait/接口，再由基础设施层实现。
- 保持模块边界稳定，不要为了单次需求打破已有抽象。

## 反模式

- Handler 中写复杂业务流程。
- Service 中拼接 SQL、直接解析 HTTP 请求、直接读环境变量。
- Domain 中依赖 ORM entity、HTTP response、JSON extractor 或具体 SDK 类型。
- Repository 返回数据库内部 entity 给上层，而不是映射到领域类型或 DTO。
