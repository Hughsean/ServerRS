# Rust 代码风格规则

## 基本要求

- 遵循 Rust 2021/2024 项目现有 edition、lint、feature 和模块风格。
- 提交前优先运行 `cargo fmt`；不要手动制造与 rustfmt 冲突的格式。
- 优先使用清晰的类型和函数名，不要为短小而牺牲可读性。
- 保持模块内已有的导入排序、分组和 `pub use` 风格。
- 不要引入未使用的依赖、未使用的 feature、未使用的导入和死代码。

## 类型与所有权

- 优先让类型表达约束，避免用裸字符串、裸整数传递有业务含义的值。
- 不要过度 clone。需要 clone 时确认所有权、生命周期和异步边界确实需要。
- 优先传引用、切片或具体领域类型；避免无意义地使用 `String`、`Vec`、`serde_json::Value` 作为内部边界。
- 只有在需要动态分发、异构集合或隐藏具体实现时才使用 trait object。

## 异步代码

- 不要在 async 上下文里执行阻塞 IO、长时间 CPU 计算或持有同步锁跨 `.await`。
- 不要在持有 `MutexGuard`、数据库事务、连接、文件句柄等资源时随意 `.await`，除非已确认安全。
- 后台任务必须有清晰的错误处理、取消语义和日志；不要静默吞掉错误。

## 依赖

- 引入新 crate 前先搜索项目是否已有等价能力。
- 新依赖必须有明确用途；避免为了小功能引入大型框架。
- 不要在库代码里随意依赖具体运行时、CLI 或 Web 框架，除非该模块本来就是对应基础设施层。
