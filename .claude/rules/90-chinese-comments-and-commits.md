# 中文注释与 Git 提交规则

## 适用范围

本规则适用于所有代码修改、脚本修改、配置修改、文档修改以及 Git 提交相关操作。

## 代码注释

* 新增代码注释必须使用中文。
* 修改已有中文注释时，继续使用中文。
* 修改已有英文注释时，优先改写为准确、简洁的中文；除非该注释属于第三方协议、标准字段、外部 API 原文或必须保持英文的机器识别内容。
* 注释应解释“为什么这样做”或“这里有什么约束”，不要重复代码字面含义。
* 不要为了满足注释要求而添加无意义注释。
* 公共 API、复杂业务逻辑、错误处理分支、并发/异步边界、兼容性处理、非显然算法必须补充中文说明。
* TODO、FIXME、NOTE 等标记可以保留英文标签，但说明内容必须使用中文，例如：`// TODO: 补充边界条件测试`。
* Rust 文档注释使用中文，例如 `///`、`//!` 中的说明文字应使用中文。
* TypeScript / JavaScript / CSS / SQL / Shell / PowerShell 等文件中的新增注释也必须使用中文。

## Git 提交信息

* 生成 Git commit message 时必须使用中文。
* 不要生成英文提交标题或英文提交正文。
* 提交标题应简洁描述本次变更，建议不超过 50 个中文字符。
* 提交正文用于说明原因、影响范围、测试方式或兼容性注意事项。
* 如果使用 Conventional Commits，类型前缀可以保留英文，描述必须使用中文。

推荐格式：

```text
feat: 增加状态栏 provider 请求统计

- 从 CC Switch 数据库读取指定 provider 的请求数
- 保留所有 provider 的默认统计口径
- 不再显示费用字段
```

## Claude 操作要求

* 当用户要求生成、修改、补充代码注释时，必须使用中文。
* 当用户要求生成 Git commit message、变更摘要、PR 标题或 PR 描述时，默认使用中文。
* 当执行或建议 `git commit -m` 命令时，提交信息必须是中文。
* 不要自动提交代码；只有用户明确要求提交时，才可以执行 Git 提交。
* 如果项目已有提交规范，优先遵守项目规范；在不冲突的前提下，提交说明仍必须使用中文。
