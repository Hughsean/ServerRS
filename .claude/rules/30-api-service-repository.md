# API / Service / Repository 通用规则

## API 层

- API 层只负责请求解析、参数校验、认证上下文提取、调用应用服务和响应转换。
- DTO 应与内部领域模型分离；不要直接把数据库实体作为请求或响应对象。
- 错误响应应使用项目统一错误模型，不要临时拼接不一致的 JSON 错误结构。
- 新增接口时同步考虑路由注册、鉴权策略、输入校验、响应结构、分页/排序/过滤约定和测试。

## Service 层

- Service 层负责用例编排，不应包含 Web 框架细节。
- Service 的输入输出应使用领域类型、命令对象、查询对象或专用 DTO，避免直接暴露 HTTP extractor。
- 事务边界应清晰：一个用例需要原子性时，由 Service 或 Unit of Work 统一控制。
- 调用外部系统时要处理超时、失败、重试、幂等和日志，不要默认外部系统永远成功。

## Repository 层

- Repository 负责持久化读写和数据库模型映射，不负责业务决策。
- 查询条件、分页、排序、软删除、租户隔离等规则应与项目已有模式一致。
- 不要把 ORM 查询对象、连接池、事务对象泄漏到上层接口中，除非该抽象已在项目中明确存在。
- 数据库错误应转换为项目统一错误类型，并保留足够上下文用于排查。
