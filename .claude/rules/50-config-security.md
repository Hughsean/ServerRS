# 配置与安全规则

## 配置

- 不要在源码中硬编码密钥、token、密码、私有 URL、生产账号、内部 IP 或绝对本地路径。
- 新增配置项时同步更新示例配置、默认值、配置结构体和文档说明。
- 配置读取应集中在项目已有配置模块，不要在业务代码中到处 `env::var`。
- 区分必填配置和可选配置；缺失必填配置时应在启动阶段失败，而不是运行时随机失败。

## 安全

- 所有外部输入都必须校验，包括 HTTP 参数、路径参数、查询参数、JSON body、文件名、回调参数和第三方事件。
- 不要把用户输入直接拼接到 SQL、shell 命令、路径、URL、日志模板或 HTML 中。
- 处理文件路径时防止路径穿越；处理 URL 时防止 SSRF；处理命令时避免 shell 注入。
- 鉴权、授权、租户隔离、用户归属校验不能只放在前端或调用方假设里。
- 删除、转账、发布、执行命令、批量修改等危险操作必须考虑权限、审计和幂等。

## 隐私

- 日志和错误响应中不要输出 access token、refresh token、cookie、authorization header、密码、验证码、私钥、完整手机号、身份证号等敏感信息。
- 测试数据应使用假数据，不要复制真实用户数据。
