# Git 与变更安全规则

## Diff 控制

- 保持提交范围小而清晰，不要把格式化、重构、依赖升级和功能修改混在一起。
- 不要修改无关文件、锁文件、生成文件或配置文件，除非任务需要。
- 修改依赖版本前先确认兼容性和影响范围。
- 不要删除注释、文档或兼容逻辑，除非确认它们错误或过时。

## 兼容性

- 公共 API、数据库 schema、配置格式、序列化字段和错误码变更都视为潜在破坏性变更。
- 需要迁移时应提供向后兼容方案、迁移脚本或明确的升级说明。
- 不要随意重命名对外字段、路由、事件名、配置名和环境变量。

## Claude Code 操作约束

- 执行破坏性命令前必须确认意图，例如删除文件、清空目录、重置分支、覆盖配置、批量替换。
- 不要自动提交 git commit，除非用户明确要求。
- 不要自动推送、发布、部署、运行生产迁移或调用生产接口，除非用户明确要求且上下文确认安全。
