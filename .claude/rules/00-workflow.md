# 通用工作流规则

## 修改前

- 先阅读与任务直接相关的文件、类型定义、调用方和测试，不要凭文件名猜测实现。
- 先确认现有约定：模块边界、命名风格、错误类型、日志方式、配置方式、测试方式。
- 只解决用户提出的问题；不要顺手重写无关模块。
- 对不确定的行为，优先通过代码搜索、测试、类型定义和现有调用点确认。

## 修改中

- 做最小可审查修改，保持 diff 聚焦。
- 保持现有 public API 兼容，除非任务明确要求破坏性修改。
- 不要删除看似无用但可能被外部调用、配置、宏、反射、序列化或 feature gate 使用的代码。
- 不要把临时调试输出、硬编码路径、硬编码密钥、测试账号或本地环境假设提交到源码。

## 修改后

- 说明修改范围、关键决策、潜在风险和验证方式。
- 如果没有运行测试或构建，明确说明未运行。
- 如果发现邻近问题但未修改，单独列出，不要混在已完成事项里。
